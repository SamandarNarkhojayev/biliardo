# S3 от ps.kz — настройка и эксплуатация

## Что и куда складывается

Создаются **два** бакета:

| Бакет | Назначение | Доступ | Что внутри |
|---|---|---|---|
| `biliardo-media` | пользовательский контент | **public-read** | аватары, логотипы клубов, фото турниров |
| `biliardo-backups` | резервные копии БД | **private** | `postgres/<db>-<UTC-timestamp>.sql.gz` |

Структура ключей в `biliardo-media`:
```
avatars/<user_id>/<timestamp>-<random>.<ext>     # JPEG/PNG/WebP/GIF, до 5 МБ
clubs/<club_id>/logo.<ext>                       # будущее
tournaments/<tournament_id>/photos/<n>.<ext>     # будущее
```

Структура `biliardo-backups`:
```
postgres/biliardo-2026-05-27T00-00-00Z.sql.gz
postgres/biliardo-2026-05-28T00-00-00Z.sql.gz
...
```
Retention — 30 дней (старше — удаляются автоматически).

## Подключение к ps.kz

ps.kz даёт S3-совместимое объектное хранилище (HotBox / Object Storage).
В личном кабинете ps.kz:

1. Закажите услугу **Object Storage** (S3-compatible).
2. В разделе «Доступ» создайте **ключ доступа** — получите:
   - `S3_ACCESS_KEY_ID`
   - `S3_SECRET_ACCESS_KEY`
3. Найдите endpoint URL — обычно вида `https://hb.ps.kz` или `https://s3.ps.kz` (точное значение смотрите в личном кабинете услуги).
4. Регион — обычно `kz-1` (если ps.kz не указывает иначе, попробуйте `us-east-1` как fallback — для AWS SDK).

Создайте бакеты:
```bash
# Через AWS CLI
export AWS_ACCESS_KEY_ID=...
export AWS_SECRET_ACCESS_KEY=...
export AWS_DEFAULT_REGION=kz-1

aws --endpoint-url https://hb.ps.kz s3 mb s3://biliardo-media
aws --endpoint-url https://hb.ps.kz s3 mb s3://biliardo-backups

# Сделать biliardo-media публично читаемым
aws --endpoint-url https://hb.ps.kz s3api put-bucket-policy \
  --bucket biliardo-media \
  --policy '{
    "Version": "2012-10-17",
    "Statement": [{
      "Sid": "PublicRead",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::biliardo-media/*"
    }]
  }'

# Включить CORS для прямой загрузки с фронта (presigned PUT)
aws --endpoint-url https://hb.ps.kz s3api put-bucket-cors \
  --bucket biliardo-media \
  --cors-configuration '{
    "CORSRules": [{
      "AllowedOrigins": ["https://biliardo.kz", "http://localhost:5173"],
      "AllowedMethods": ["GET", "PUT", "HEAD"],
      "AllowedHeaders": ["*"],
      "ExposeHeaders": ["ETag"],
      "MaxAgeSeconds": 3000
    }]
  }'
```

## Переменные окружения

Добавьте в `.env.prod` (для docker-compose.prod.yml):

```env
# ps.kz S3
S3_ENDPOINT=https://hb.ps.kz
S3_REGION=kz-1
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
S3_BUCKET_MEDIA=biliardo-media
S3_BUCKET_BACKUPS=biliardo-backups
# Опционально — если за бакетом стоит CDN или собственный домен
S3_PUBLIC_URL=https://media.biliardo.kz
# Бэкапы
BACKUP_RETENTION_DAYS=30
```

Для локального dev (`.env` в `services/auth/`):
```env
S3_ENDPOINT=https://hb.ps.kz
S3_REGION=kz-1
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
S3_BUCKET_MEDIA=biliardo-media-dev
```

## Как работает загрузка аватара

Использован паттерн **presigned URL** — файл идёт от клиента сразу в S3, минуя бэкенд (нет нагрузки на auth-сервис).

```
[Browser]                  [auth API]                   [S3 ps.kz]
   │  POST /me/avatar/upload-url
   │    { contentType, size }
   ├──────────────────────►│
   │                       │ presign PutObjectCommand
   │                       │ (TTL 5 min, ContentLength fix)
   │  { uploadUrl, publicUrl }
   │◄──────────────────────┤
   │
   │  PUT uploadUrl
   │  (binary file body)
   ├──────────────────────────────────────────────────►│
   │                                          200 OK   │
   │◄──────────────────────────────────────────────────┤
   │
   │  PATCH /auth/me { avatar: publicUrl }
   ├──────────────────────►│
   │                       │ user.avatar = publicUrl
   │            { user }   │
   │◄──────────────────────┤
```

Ограничения встроены в presign:
- `ContentLength` фиксирован — S3 откажет в апдейте, если клиент попытается прислать больше.
- `ContentType` фиксирован — на стороне auth проверяется в whitelist (JPEG/PNG/WebP/GIF).
- TTL ссылки — 5 минут.

## DB-бэкап

Скрипт `scripts/backup-db.sh` запускается **сервисом `backup`** из `docker-compose.prod.yml`. Каждые 24 часа делает `pg_dump | gzip | aws s3 cp`. После загрузки удаляет файлы старше `BACKUP_RETENTION_DAYS` дней.

Запуск вручную:
```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod \
  run --rm backup bash /usr/local/bin/backup-db.sh
```

Восстановление:
```bash
# 1. Скачать дамп
aws --endpoint-url $S3_ENDPOINT s3 cp \
  s3://$S3_BUCKET_BACKUPS/postgres/biliardo-2026-05-27T00-00-00Z.sql.gz \
  /tmp/restore.sql.gz

# 2. Восстановить
gunzip -c /tmp/restore.sql.gz | psql -h <host> -U billiard -d billiard
```

## Безопасность

- **Никогда** не коммитьте `S3_SECRET_ACCESS_KEY` в git. Используйте `.env.prod` (в `.gitignore`).
- В ps.kz рекомендуем создать **отдельные ключи** для:
  - `biliardo-media` (read/write только на этот бакет) — для бэкенда
  - `biliardo-backups` (write+list, без delete для исторических) — для бэкап-сервиса
  Это даст изоляцию: компрометация одного ключа не вытащит другие данные.
- Для `biliardo-backups` отдельно подумать про versioning и MFA delete — на случай ransomware.

---

## Что НЕ закоммичено и нужно сделать руками

1. Создать бакеты `biliardo-media` и `biliardo-backups` в ps.kz.
2. Получить ключи и заполнить `.env.prod`.
3. Применить CORS и bucket policy (команды выше).
4. Запустить `docker compose -f docker-compose.prod.yml up -d backup` — поднимет фоновый бэкап-демон.
5. Через сутки убедиться, что в `biliardo-backups/postgres/` появился свежий дамп.
